2 · The structure

Four layers, and one door

Screens never touch the stored data. They ask the rules, and the rules go through one door: the store door (REACH rule R7). Today the door leads to storage on this computer. Later the same door also talks to the shared server, and only the door changes, not the screens.

Screensapps/desktop
The June screens, in React: menu, Overview, Store and bags, item page, count, stock takes, register, staff, settings, activity. They only draw what the rules hand them, and show plain text only (B4).
↓ ask ↑ answer
Rulespackages/core
Every rule from the Master Checklist, as small functions with a test each: readiness (B1, B25, B10), whole numbers (B17), counts (B16), the register (Q13–Q16), month-safe dates (B26), the 24-hour delete (Q38), import checks (B15, B6). No screen code, so EDP and later phone apps can reuse them.
↓ save · read ↑
Store doorpackages/store
The only way in or out. Every change becomes a message with its own ID, the person, the time and the app (R8, R9). It writes the message, updates the stored records, adds the log entry, and shows a red light if the save fails (B22). It carries data across new versions; it never replaces data (B3).
↓
This computerIndexedDB
Every computer keeps its own full copy, so the program opens and works with no internet (F3, Q9). Changes made offline wait in an outbox.
Shared serverlater · REACH SD2
One copy for everyone: the doctor's Mac and the nurses' Windows PCs see the same stock (Q5). Where it runs is a REACH decision (EDP Q44), not made yet. See “Depends on”.

Data

What is stored, and in what shape

Every record carries the REACH Core stamps (R4): a hidden random id · createdAt / createdBy · changedAt / changedBy · country · state (Active or Archived). Moments are stored in UTC; calendar dates (expiry, course done) as plain dates (R6, B13). Records point to each other by ID, never by copying a name (R5); a frozen stock take keeps names as they were on the day.

The real program

An installed program on Mac and Windows

Proposed: Electron

The screens run inside the program's own built-in browser engine (Chromium), the same on Mac and on Windows. What I test is exactly what the nurses get. Installs like any program and opens with no internet. Used by Slack, VS Code, Teams.

Not chosen: Tauri

Smaller files, but it draws with Safari's engine on a Mac and Edge's on Windows, so the same screen can look and behave differently on the doctor's Mac and the nurses' PCs. It also needs the Rust toolchain on this Mac.

Not chosen: an installable web page

You asked for “a real app, not a web page” (Q4), and REACH rule SD8 says no web apps.

What's yours to do, later (Stage 9, not now)
  • Mac: so the Mac opens it without a warning, it's signed with an Apple “Developer ID Application” certificate (Apple developer portal › Certificates). It's different from the App Store certificate. I'll give you the exact clicks when we get there.
  • Windows: without a paid code-signing certificate, Windows shows a one-time “unknown publisher” warning. Fine for testing; decided before the nurses get it.
  • The same choice should go to EDP's real program (EDP P4), so I'd raise it in the REACH chat.

Depends on

Three things this project doesn't decide

1 · Where the shared server runs (REACH SD2, EDP Q44)

Everything can be built and tested on one computer through the store door. But release 1 can't go to the nurses until there's a server: the doctor's Mac and the nurses' PCs must see the same stock (your Q5). REACH planned to decide it when EDP needs shared data. This app may need it first. I'd bring it to the REACH chat before Stage 6 ends.

2 · Sharing the REACH Core code between apps

Every REACH app needs the same IDs, stamps, message and backup shapes. For now I'd write them here, in packages/core/src/reachCore/, kept separate so they can move into one shared package later. Where that package lives is a REACH decision (R13).

3 · Sign-in accounts (REACH SD1, EDP F61)

Real accounts need the server too. Until then, the program uses this app's own people list with a password per person on each computer, built behind the same door so it can be switched to the REACH accounts later.
