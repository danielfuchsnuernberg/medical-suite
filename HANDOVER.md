## How to run it
In Terminal, in this folder: `npm start` (builds, then opens the program). First time on a Mac: `npm_config_cache=<a scratch folder> npm install`; if Electron doesn't start, `node node_modules/electron/install.js` (npm 11 skips Electron's own install step).

## Known limits
- Until the server exists (REACH SD2): each computer has its own passwords; a Manage-level person gives one-time passwords per computer. If two computers change levels at the same time while offline, both are accepted when they sync, so in theory both last managers could be lowered; the server will check this. There is no lock-out after many wrong passwords yet; anyone with the computer can read the program's data folder anyway.
- A manager who lowers their own level loses Settings at once (nothing asks first).
- A program that was already used before F5 (e.g. Danny's own copy) keeps its data: its items get category records, but it has no base settings, departments or courses until someone adds them in Settings (it says “Base not named yet” and uses the computer's time zone until then). Only a new, empty program gets the full DEMO lists.
- Controlled drugs change only through the register (Controlled drugs in the menu). A request reaches a doctor on any computer that has synced; a message to the doctor's phone needs the real server (REACH SD2). A doctor's PIN is per computer. Your own older copy: people have no profession yet; Management sets them in People and access, each doctor types their medical code at sign-in, then the first doctor is set (once) and a doctor opens each drug's register at what the shelves hold. The item page's EDP panel waits for F17. The expiry box follows the Mac's date order (the date is written out under it). The new DEMO lines (Trauma kit, Gloves) appear only in a new, empty program.
- Store versions: messages that arrive from a computer still running an older version are not reshaped; until the server exists, update every computer together.
- Activity: people from other apps show by their ID (e.g. “edp-dispatcher”) until the people lists are joined (REACH R2). The log is rebuilt from all messages after each change; fine for now, to be measured with the real stock list.
- Backups: kept in the program's folder on this computer (one a day, last 30); the server's nightly backups wait for REACH SD2. A restore replaces this computer's data; with a server, how a restore reaches other computers is decided with SD2. Passwords and PINs are never in a backup.
